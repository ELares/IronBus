# IronBus design diagrams

This directory holds the architecture and design diagrams for IronBus, rendered as PDFs. They are a visual companion to the design issues; the GitHub issues remain the canonical, authoritative design record. Each diagram is committed both as a Graphviz source (`.dot`) and a rendered `.pdf`, so anyone can regenerate them.

For the byte-level data-model reference (the on-disk, wire, config, runtime, and report contracts derived from and cross-checked against the source), see [CONTRACTS.md](CONTRACTS.md).

Regenerate all PDFs:

```sh
cd docs/diagrams
for f in *.dot; do dot -Tpdf "$f" -o "${f%.dot}.pdf"; done
```

- [The durability contract and the levels model](DURABILITY.md): the authority for IronBus's durability contract. States honestly that v1 ships exactly ONE durability level, the safe `sync` level (ack-implies-durable, invariant I2): a `Pub`/`PubAck` is emitted only after the covering `fdatasync` returns, the #177 group-commit amortizes the sync but never acks before it (so the #50 "batch" level is the same safe level, not a relaxation), and acknowledged loss on power loss is zero. Maps every #50 acceptance criterion to the EXISTING mechanical falsification, citing the real tests (the ack-never-precedes-the-fsync property `..._i2` in `actor.rs`, the power-loss boundary sweeps, the fsyncgate no-false-success + writer-freeze EIO tests, crash-after-create surviving via the parent-directory fsync, group-commit one-`fdatasync`-per-batch, and the stop-at-first-bad-frame corruption corpus), and marks each PROVEN-today versus waiting-on-the-relaxed-levels. DESIGNS the relaxed `interval` and `async`/`none` levels as SPECIFIED-NOT-IMPLEMENTED opt-ins with their worst-case-loss bounds (interval bounded by the flush window, async unbounded until the next sync), off by default, an explicit data-loss acknowledgement, and the #14 config keys, flagging clearly that they trade durability for throughput contrary to the safe default and are not wired. Scopes the across-levels throughput/latency/bytes-at-risk curve on real ARM SD/eMMC as a DEVICE residual that needs both the relaxed levels and the reference hardware, not faked host-side, feeding #19. Cross-references INVARIANTS.md, WAL.md, SLO.md, EDGE_TUNING.md, and the loss-report schema; docs only, no source changed (#50, #6).
- [The recovery model: longest valid prefix and stop at first bad frame](RECOVERY.md): the authority for IronBus's recovery model, RATIFYING the shipped architecture and SUPERSEDING the older draft criteria (#43, #53, #57, #58). States plainly that recovery is STOP AT FIRST BAD FRAME / LONGEST VALID PREFIX, not the drafts' byte-by-byte two-record resync with mid-log skip-and-resume. Specifies the durable floor (segment header per-segment floor, footer-as-candidate, checkpoint as a conservative floor never a ceiling), the intact-record predicate (magic + version==1 + header_crc + total_len sentinel + body_crc + optional xxh3-64, cited to CONTRACTS.md and codec.rs), longest-valid-prefix truncation labeled not-data-loss for a torn tail, and stop-at-first-bad-frame dropping [bad, EOF) as one bounded+reported corruption loss event under the I3 caps, with timestamp NEVER participating (I6). Delivers the exhaustive DECISION TABLE (one row per recovery situation mapping condition to action, reason code or none, data-loss yes/no, and the owning code symbol or corruption-corpus test), the decidable TORN-TAIL versus MID-LOG classification and the copy-then-drop quarantine handoff, active-segment handling (sealed-highest rolls forward to a fresh-id segment; unsealed tail truncates-and-resumes; a corrupt active-segment header fails closed), the single safe hardcoded recovery behavior (no strict/salvage modes; a future #14 knob noted as a candidate, not shipped), and the SUPERSEDED two-record resync + 8 MiB scan window + poison-set memoization of #57 with the #5 magic-is-not-a-resync-authority rationale. Records every divergence from the drafts honestly (zero-fill classification, SequenceGap reserved-but-unproduced, the dropped resync). Cross-references CONTRACTS.md, DURABILITY.md, INVARIANTS.md, WAL.md, COMPATIBILITY.md, and the loss-report schema; docs only, no source changed (refs #43, #53, #57, #58).
- [Cross-platform segment preallocation, and why v1 never recycles](PREALLOCATION.md): the DESIGN spec (specified, not yet implemented) for portable segment preallocation, the half of #135 that assumed Linux `fallocate` and so left a portability hole the Cross Platform tagline does not allow. Defines a thin four-primitive shim (preallocate, file-datasync, directory-sync, sealed-read-map) over the existing `RandomAccessFile` / `Filesystem` IO seams, with the three durability primitives already implemented and preallocate the one specified here; maps preallocate to its per-OS syscall with a per-OS durability note (Linux `fallocate`/`posix_fallocate`, macOS `fcntl(F_PREALLOCATE)` + `ftruncate`, Windows `SetEndOfFile` plus the privileged `SetFileValidData` caveat), each with a correct fallback ladder down to grow-on-append. Specifies preallocation default ON to full roll size and its wear/latency rationale (a contiguous file, one fewer inode-metadata fdatasync per commit; Edge First), and makes ENOSPC at roll a fail-fast event routed to the #10/#13 overflow path rather than a mid-stream surprise. RESOLVES the recycling question honestly: v1 NEVER recycles a segment id (ADR 0002, because `segment_id` is the at-rest AEAD nonce high bits, #108), so no generation stamp is added to the #5 header (it is unnecessary when ids are never reused), and recycling becomes a v2 concern gated behind a nonce-safety decision (a per-life random nonce prefix or a key rotation on recycle). Flags the cross-platform build implications to #17. Cross-references WAL.md, CONTRACTS.md, AT_REST_ENCRYPTION.md, RISK_REGISTER.md, and ADR 0001/0002; docs only, no source changed (#40, #4).
- [Optional key-based log compaction (the no-manifest design)](COMPACTION.md): the DESIGN spec (specified, not yet implemented) for IronBus's optional, opt-in, Kafka-style key-based log compaction (#83), reconciled with the no-manifest directory-of-self-describing-files model. The issue assumes an atomic MANIFEST swap; IronBus has no manifest, so the design ADAPTS it: a compacted segment self-describes its COVERED offset range and a COMPACTED marker in its header (the marker is one `flags` bit, the covered end-offset and highest-covered source id fit the existing reserved 16 header bytes, but interpreting them honestly requires a format-version bump so a v1 reader fail-closed refuses a compacted log rather than misreads it). The SINGLE atomic commit point is the durable appearance of the new compacted segment (the directory fsync), after which the originals are rename-then-unlinked so open readers drain rather than read freed bytes. Recovery resolves a compacted-vs-original overlap deterministically from the self-describing headers alone (a compacted segment supersedes every original it fully covers; a higher segment id breaks a two-compacted tie), via the existing longest-valid-prefix with NO compaction-specific repair (crash before the commit discards the orphan new segment, crash after unlinks the superseded originals), neither path a reported loss. Covers the full acceptance design: at-least-the-last-value-per-key, tombstone retention for `tombstone_ttl` (default 24h), never reorder or rewrite offsets (survivors keep ORIGINAL offsets, producing sparse ranges), never compact the active segment, sparse-offset reader/index tolerance with a new non-loss `Compacted` gap marker (coordinated with #9 and the #59 SkipEvent, excluded from loss-bytes), the cleaner rate-limited + yielding to appends + OFF by default, and `compact_and_delete` running the age/size reaper FIRST. States honestly it is specified-not-implemented and edge-hostile (CPU + flash cost). Linked from `docs/WAL.md`; docs only, no source changed (#83, #13).
- [Trained per-type dictionary lifecycle (the self-contained-distribution design)](DICTIONARY_LIFECYCLE.md): the normative DESIGN spec (specified, not yet implemented) for IronBus's trained per-message-type compression dictionaries (#78, parent #12), the highest-ratio lever for the tiny similar telemetry payloads, designed so a referenced dictionary never strands an offline reader. Specifies the offline `ironbus dict train` subcommand (a per-type REAL-telemetry sample corpus with `MIN_SAMPLES`/`TARGET_SAMPLES` floors, emitting an opaque `dicts/<dict_id>.zstd` blob and a `--json` summary), a `dict_id` that is a u32 truncation (first 4 bytes, little-endian) of BLAKE3-256 of the dictionary bytes, collision-checked and REFUSED fail-closed at train time so the id is content-addressed and reuse is structurally impossible with NO central registry. Makes distribution self-contained two ways: the producing node writes each referenced dictionary as a per-segment on-disk SIDECAR under a `dicts/` subdirectory (content-named, so the file name is its own integrity check; parallel to `quarantine/`, invisible to the recovery walk; written durably before the referencing segment is acked), AND the active set is EMBEDDED in the static binary via `include_bytes!` (#17) so a fresh node with an empty data dir still decodes. A reader resolves the on-disk SIDECAR FIRST then the EMBEDDED set, the order that survives a binary DOWNGRADE (the sidecar travels with the data; the embedded set is fixed at the reader's build time and can be stale). An UNRESOLVED dict_id is bounded poison via #8, NEVER a silent drop or crash: it is a NEW failure class (framing and CRCs intact, only the decode input absent, the at-rest-encryption "unknown key-id" shape), routed as a NEW APPEND-ONLY loss reason `UnresolvedDictId` (code 7, label `unresolved_dict_id`, counts as data loss) that does NOT renumber codes 1-6 and does NOT bump `schema_version`, justified against the frozen loss-report.v1 rule. Dictionaries are append-only: rotation writes a NEW dict_id, never mutates an existing blob, so old data stays readable forever (the sidecar, not the embedded set, is authoritative for old data). Specifies the before/after per-batch ratio METHOD (one variable held against a real per-type corpus, the `ironbus bench` realized-ratio surface and the #114 matched-workload rig, on-device per #19/#113) with the measured number left as a residual. Proves the design is ADDITIVE: the v1 record frame already RESERVES a u32 dict_id in the compressed payload's self-describing descriptor behind the `RecordFlags::COMPRESSED` bit, with `dict_id=0` the no-dictionary sentinel and `COMPRESSED` never set in v1, so no wire or on-disk format breaks. Honest that the `ZDICT` training call (and the opt-in zstd dependency per ADR 0003), the sidecar IO, the embed, the `UnresolvedDictId` emission, and the measured ratio are the implementation follow-up. Cross-references CONTRACTS.md, the loss-report schema, INVARIANTS.md, DISTRIBUTION.md, CLI.md, and ADR 0002/0003; docs only, no source changed (#78, #12).
- [Threat model and security posture](THREAT_MODEL.md): the enumerated edge threat model, the implemented DoS and resource-exhaustion mitigations cited to the code, and an honest statement of the current no-auth / no-TLS / no-at-rest-encryption posture versus the specified controls (#106 to #109), each cross-checked against the source (#105).
- [Backpressure: time-in-queue shedding, retry budgets, and load shedding](BACKPRESSURE.md): the normative design spec (mostly specified, not yet implemented) for two overload controls under the backpressure parent (#10). CoDel (RFC 8289) time-in-queue shedding (#68) sheds on sojourn not depth, so the control is rate-independent and needs no per-device tuning: TARGET 5 ms / INTERVAL 100 ms defaults exposed per topic via #14 but clamped (TARGET in [1 ms, 1 s], INTERVAL in [20 ms, 10 s]), the `INTERVAL/sqrt(count)` drop-spacing law, sojourn measured on the monotonic clock seam (`Clock::now_monotonic_nanos`) clamped `>= 0` with the interval window reset across a detected suspend/resume gap so a sleeping edge device cannot misfire, and a sojourn-independent depth-and-byte backstop that fires the overflow policy when a fully stalled drain produces no sojourn samples (proven to bound memory under a total stall). The retry-and-shedding spec (#69) caps retries at a per-client budget of 10% of the client's request rate over a sliding 60 s window (SRE adaptive throttling, accept-based, K~2) enforced client-side AND re-checked broker-side, specifies the structured `retry_after_ms` (0 = retry-now, 0xFFFFFFFF = do-not-retry/shed) and `shed` wire fields for #11, a separate per-connection fire-and-forget token bucket (5000 msg/s, 5 MiB/s, 100 ms refill) that caps the uncontrolled tier and cannot evict credited traffic, and a static-floor-16 egress AIMD concurrency limiter bounded [4, 128] (+1 clean window, x0.5 on timeout/429/503) with Vegas/Gradient2 deferred behind the interface (proven not to amplify into a retry storm). Honest about specified-vs-implemented: IronBus today ships only drop-new/drop-oldest overflow and per-consumer credit; CoDel, the retry budget, the wire fields, the token bucket, and the egress limiter are SPECIFIED, and the wire fields require a #11 frozen-protocol extension. New #14 keys and #16 metrics tabled. Cross-references WAL.md, METRICS.md, CONTRACTS.md, THREAT_MODEL.md, RISK_REGISTER.md, EDGE_TUNING.md, and the clock seam (#68, #69, #10, #14, #16, #11).
- [Wire flow control: the FLOW credit body and the producer PFLOW direction](FLOW_CONTROL.md): the normative spec that freezes the `Flow` frame (tag 10) carrier and its wire-visible state machine for issue #72 (parent #11). Part 1 (the consumer credit direction, IMPLEMENTED in its reduced form) freezes the FLOW body layout (`credits` u32 LE leading, then an optional `dir_flags` byte, an optional `byte_credits` u32, and an optional `misc` byte), pinned to IronBus's fixed-width-little-endian canonical form (NO LEB128 varints, per the CONTRACTS.md convention, reconciling the issue's varint prose with the shipped format), the decrement-on-send / restore-on-ack per-connection credit accounting (`consumer_credit` = 64, `consumer_credit_bytes` = 8 MiB, the leased set is the accounting), the zero-credit hold (deliver nothing, never drop leased or available traffic), and the reconnect credit-reset rule (re-advertised per connect, never inherited, the mitigation for the dominant credit-desync-after-reconnect stall). Part 2 (the producer PFLOW direction, SPECIFIED not implemented) freezes the byte/second budget (default unlimited via the `0xFFFFFFFF` sentinel), the one-bit pause (`misc` bit 0, clear by default, asserted only under disk-spill/memory pressure per #10), and the fire-and-forget drop-and-report-with-a-grace-window behavior, tied to (not redefining) the BACKPRESSURE.md fire-and-forget token bucket (5000 msg/s, 5 MiB/s, 100 ms refill) and the drop-new/drop-oldest disposition every shed funnels into, with the accept loop never blocked and leased/acked publishes exempt from producer drop. Part 3 frames it as a forward-compatible frozen-frame extension (the four-byte body is a strict prefix of the structured body; PFLOW reuses the `Flow` tag with a direction bit, adding no new frame type) whose body is empty of these fields today and whose WIRING (the structured codec, broker PFLOW assertion, producer honor logic, capability negotiation in the empty `Connect`/`Info` handshake) is the implementation residual owned by #11 / #72-impl. Cross-references BACKPRESSURE.md, CONTRACTS.md, COMPATIBILITY.md, compat/versions.md, METRICS.md, WAL.md, and the session/engine/frame source. Docs only, no source changed (#72, #11).
- [Connection-scoped authentication and the three-scope authorization model](AUTHENTICATION.md): the normative (specified, not yet implemented) auth contract every verb is gated by. Specifies the three v1 authentication mechanisms (bearer token stored as SHA-256 and constant-time compared, username/password hashed with Argon2id at the edge profile m=19 MiB / t=2 / p=1, and mTLS whose identity is the first URI-then-DNS SAN with CN excluded and a verifying-but-unmatched cert rejected), the three explicit authorization scopes (publish, subscribe, admin, where admin does NOT imply the others), the admin-gated verb and #15 diagnostic list, additive credential-set rotation with no expiry timer, and the single uniform Authorization Violation error with no bad-credential-vs-insufficient-scope oracle. Establishes auth once in the #11 CONNECT handshake and binds it to the connection for its lifetime; cites where it constrains the #11 handshake, the #14 config keys, and the #15 diagnostics. Cross-references THREAT_MODEL.md, CONTRACTS.md, COMPATIBILITY.md, INVARIANTS.md, and CLI.md (#106).
- [Transport security, the bind invariant, and pre-auth DoS defenses](TRANSPORT.md): the normative spec (specified, not yet implemented) for the TLS 1.3-only transport (no 1.2 fallback, the restricted TLS 1.3 AEAD cipher set, rustls bundled in the binary, mandatory server-cert verification on clients with mTLS as the optional strongest mode), the fail-closed bind invariant (default loopback; any non-loopback bind requires BOTH TLS material AND a configured auth identity, validated before the listener opens, with no override into network-plaintext or network-anonymous), and the pre-auth DoS defenses on by default for a non-loopback bind and exempt on loopback (a half-open pre-auth connection cap default 128, a per-source-IP connection rate limit default 10/sec token-bucket, and a failed-auth lockout at N=5 with a fixed escalating accept delay that keeps the auth compare constant-time), each a #14 config key with a safe default and each traced to the THREAT_MODEL.md threat row it closes (#107).
- [Optional at-rest AEAD encryption](AT_REST_ENCRYPTION.md): the normative spec (specified, not yet implemented) for optional, off-by-default authenticated encryption of segment record bodies, the device-theft (T1) mitigation. Specifies the runtime AEAD selection (AES-256-GCM where hardware AES is reported, ChaCha20-Poly1305 as the portable constant-time fallback), chosen once at startup and RECORDED in the segment header so reads are unambiguous; the deterministic 96-bit nonce (segment-id || per-segment record counter) that makes nonce reuse structurally impossible without trusting an early-boot RNG; in-place body encryption that leaves the #6 publish path and segment-rolling contract unchanged with #5 checksums computed over CIPHERTEXT so corruption detection works without the key; a key-id (never the key) in the header with new-segments-only rotation and a #14 key-source priority (TEE-sealed, raw key file, Argon2id-from-passphrase); a distinct REPORTED loss class for an unknown key-id or an AEAD tag mismatch routed through #8, separate from a #5 checksum corruption so a wrong or rotated key is never silent; and the honest limit that a key co-located on a stolen device defeats it. Coordinates the new header fields with #4/#5 to avoid framing drift. Cross-references THREAT_MODEL.md, CONTRACTS.md, INVARIANTS.md, COMPATIBILITY.md, and the loss-report schema (#108).
- [Secret handling, redaction, security audit events, and the crypto SBOM posture](SECRETS.md): the normative spec (specified, not yet implemented) for how secrets are sourced, protected, and never leaked. Secrets (token / password hashes, the TLS private key, the at-rest key) are sourced from a file or environment-variable reference (#14), never inline in config, and the broker fail-closed refuses to start if a secret-bearing file is group/world-readable (`mode & 0o077 != 0`) or wrong-owner, matching OpenSSH StrictModes (skip-with-notice on non-POSIX). A redacting newtype wraps every secret type so `Debug`/`Display` emit a fixed placeholder, key material is zeroed after use, and one security-event emitter takes the identity name (safe) and never the credential, pinned by a redaction unit test that asserts a known secret never appears in any log, error, or #15 dump. Defines a structured, secret-free security audit-event schema exported via #16 (authn outcome, authz denial, rate-limit / lockout trips, secret-permission boot refusal, identity reload), each carrying a monotonic sequence number plus wall-clock so ordering survives a clock jump, and enumerates the crypto dependency surface (rustls, the AEAD and Argon2 crates) shown to fit the #17 cargo-auditable SBOM under the cargo-deny advisory / license gate. Cross-references THREAT_MODEL.md, AUTHENTICATION.md, TRANSPORT.md, METRICS.md, CLI.md, and RELEASING.md (#109).

- [Edge run discipline: the protocol that makes edge numbers trustworthy](EDGE_RUN_DISCIPLINE.md): the SPECIFIED run-discipline protocol (not yet instrumented) that a canonical edge benchmark number must be produced under before it can be quoted or ratified, so multi-hour tail drift is attributable to IronBus and not to CPU throttling or flash garbage collection. Specifies thermal control (named reference active cooling, junction-temperature + per-core CPU-frequency logging per 30 s window, and a throttle event during the steady-state window FAILS the run while a warm-up throttle resets the detector); storage state (fix the exact card/eMMC model, secure-erase or `blkdiscard`+format to a known state before each canonical run, run at a fixed 50% incompressible fill, report write amplification and device temperature); harness isolation (pin the shipping broker and the harness to DISJOINT `cpuset`/`taskset` CPU sets on the 4-core edge devices, budget and report harness CPU/RSS separately from the broker's, and offload the generator to a second box on edge-min when pinned-core contention exceeds 90% busy); the steady-state criterion (warm-up = `max(60 s, page-cache-fill + 2 segment rolls)`; declare steady when 5 consecutive 30 s windows show throughput `CoV <= 3%` AND `p99 drift <= 10%`, with the exact CoV and drift formulas); the mandated `>= 4h` sustained run per release that PASSES only if hour-1-to-hour-4 `p99 drift < 25%`; and the write-amplification gate (reported every run, `>= 4x` data-dir write amplification on edge devices FAILS, per the parent #19 gate).
