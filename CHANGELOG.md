## [Unreleased]

### Security
- `docs/AT_REST_ENCRYPTION.md`: the normative spec (specified, not yet implemented) for optional, off-by-default AEAD encryption of segment record bodies (the device-theft mitigation). Specifies runtime suite selection (AES-256-GCM where hardware AES is reported, ChaCha20-Poly1305 portable fallback) recorded in the segment header, a deterministic 96-bit nonce (segment-id || per-segment record counter) with the no-reuse argument, in-place encryption that leaves the #6 publish path unchanged with #5 checksums over ciphertext, a header key-id (never the key) with new-segments-only rotation and a #14 key-source priority, an unknown-key-id / tag-mismatch reported loss class routed through #8 distinct from #5 corruption, and the honest co-located-key limit. New header fields reuse the reserved segment-header bytes so #4 framing does not drift; linked from `docs/README.md` and cross-linked from `docs/THREAT_MODEL.md`. Docs only, no source changed (refs #108).
- `docs/SECRETS.md`: the normative spec (specified, not yet implemented) for secret handling, redaction, security audit events, and the crypto SBOM posture. Secrets source from a file or env-var reference (#14), never inline; the broker fail-closed refuses to start on a group/world-readable (`mode & 0o077 != 0`) or wrong-owner secret file (OpenSSH StrictModes, skip-with-notice on non-POSIX). A redacting newtype gives every secret a fixed `Debug`/`Display` placeholder and is zeroed after use, one emitter routes security events by identity name never the credential (a redaction unit test pins it), the structured secret-free audit-event schema exports via #16 with a monotonic sequence plus wall-clock, and the crypto surface (rustls, the AEAD and Argon2 crates) is shown to fit the #17 cargo-auditable SBOM under the cargo-deny advisory/license gate. Linked from `docs/README.md` and cross-linked from `docs/THREAT_MODEL.md`. Docs only, no source changed (refs #109).
- `docs/TRANSPORT.md`: the normative spec (specified, not yet implemented) for the TLS 1.3-only transport (no 1.2 fallback, the restricted TLS 1.3 AEAD cipher set, rustls bundled in the binary, mandatory server-cert verification on clients with mTLS as the optional strongest mode), the fail-closed bind invariant (default loopback; a non-loopback bind requires BOTH TLS material AND a configured auth identity, validated before the listener opens, no override into network-plaintext or network-anonymous), and the pre-auth DoS defenses on by default for a non-loopback bind and exempt on loopback (half-open pre-auth connection cap 128, per-source-IP rate limit 10/sec token-bucket, failed-auth lockout at N=5 with a fixed escalating accept delay that keeps the auth compare constant-time), each a #14 key with a safe default and traced to the THREAT_MODEL.md threat row it closes; linked from `docs/README.md` and cross-linked from `docs/THREAT_MODEL.md`. Docs only, no source changed (refs #107).
- Release machinery: the `Release` workflow now builds the three static musl binaries with the reproducible invocation from RELEASING.md (`SOURCE_DATE_EPOCH`, `--remap-path-prefix`, `--locked`; forwarded into the cross container via a new `Cross.toml`), ships one consolidated `SHA256SUMS` alongside the per-binary `.sha256` and the cargo-auditable SBOM, attests every artifact (binaries + `SHA256SUMS` + SBOM) with a keyless Sigstore build-provenance attestation, and marks a `v0.x` tag as a prerelease. It stays dormant until a `v*` tag is pushed. Added `scripts/install.sh`, a fail-closed `curl | sh` installer that detects the arch, downloads the matching binary and `SHA256SUMS`, verifies the SHA256 before installing (optional `--verify-provenance` via `gh attestation verify`), and refuses to install on any download error, checksum mismatch, or unsupported platform, with no skip-verification override and no `eval` of remote content. On an UPGRADE the installer now retains the prior binary as `ironbus.prev` next to the destination (an atomic same-directory `mv`) BEFORE the atomic swap of the new binary into place, giving a real rollback copy (#133 step 10); the retention happens only AFTER verification passes, so it never weakens verify-before-install, and a FRESH install creates no `.prev`. A tamper-rejection test (`crates/ironbus-cli/tests/installer_verify.rs`) proves a tampered binary, an unlisted asset, an empty or malformed `SHA256SUMS`, and a missing binary are rejected while a matching binary is accepted, and two added tests prove an upgrade retains the prior bytes as `ironbus.prev` while a fresh install creates none. The broader cosign-keyless + offline-minisign + identity-pinned trust root from the issue is deferred behind the shipped SECURITY.md attestation method; `.deb`/distroless packaging is #104 (refs #103, #102, #133).
- Pinned every GitHub Actions `uses:` in the CI and nightly workflows to a full commit SHA, with the human-readable tag kept as a trailing comment (#142). A mutable tag like `@v4` lets a compromised or retagged action run with the workflow's permissions; a SHA is immutable. `dtolnay/rust-toolchain` is pinned to a single SHA and the MSRV job passes `toolchain: "1.78.0"` explicitly (the bare `@stable` uses keep the action's `stable` default), so the toolchain selection no longer rides on a mutable ref.

### Changed
- The wire server now owns the engine behind a single append-actor thread instead of an `Arc<Mutex<Engine>>` held across the produce fsync (#177). Connection handlers fan in over a bounded `sync_channel` and send commands; the actor group-commits a drained batch of produces with ONE `fdatasync` and acks the whole batch only after it. This removes the head-of-line block (a stalled disk no longer freezes every connection) and amortizes the fsync. Pings are answered in the handler without touching the actor, so a stalled produce fsync cannot block another connection's ping (the explicit acceptance test, proved with a sync-gating fault fs). I2 (ack-after-sync), single durable order, no-deadlock (a closed channel is a typed `ActorGone`), and the #195 graceful-shutdown drain (flush + checkpoint every group) are preserved. Also folds in the #176 O(n^2) re-decode fix: the read loop uses the frame parser's `Incomplete { needed }` hint to avoid re-decoding a trickled near-cap frame until it is whole (refs #177, #176, #1).
- The `ironbus-core is IO-free` CI check is now structural, not a source-text regex. A new dev-only workspace member `tools/io-free-check` parses every `crates/ironbus-core/src/*.rs` with `syn` and walks the AST for forbidden references (`std::{fs,net,process,os,io}`, `tokio`/`async_std`/`smol`/`mio`, and `extern` FFI blocks), expanding grouped/aliased/glob `use` trees to their real paths, so it cannot be evaded by import grouping, aliasing, whitespace, or a comment the way a line regex can; `std::fmt`/`core::fmt` stay allowed. The `cargo tree` dependency check is kept as the second half of the guarantee (it catches IO arriving by re-export, which the source walk cannot see). The check binary is no dependency of any shipped crate, so `syn` never enters ironbus-core's own dependency graph, and a unit-test suite proves fail-on-violation (grouped, aliased, glob, fully-qualified) and pass-on-clean (refs #143, #16, #21).
- Corrected the stale README compression row to match the frozen #139 decision: lz4_flex is the default codec (pure Rust) and zstd is opt-in only behind a feature, never on the default path. The row previously read "zstd default, per-batch, lz4 fallback", which contradicts `deny.toml` and `docs/adr/0003` (refs #139, #12).
- Replaced the overloaded generic `Ok` response frame with distinct, self-describing response frames per verb (#179): `PubAck` (tag 14, body: the durable offset as an 8-byte LE u64), `AckStatus` (tag 15, body: a one-byte status, 0 = fenced / 1 = committed-requeued-extended / 2 = progress cap reached), and `FlowEnd` (tag 16, body: the delivered count as a 4-byte LE u32). Previously a single `Ok` carried three incompatible body shapes disambiguated only by the client remembering its last request, which was undocumented at the frame level and foreclosed request pipelining. The frame type now disambiguates the reply, so a pub offset can no longer masquerade as a one-byte committed ack. `Err` stays distinct; `Ok` is retained as a reserved body-less success and the new tags are pinned by the frozen-tag test (refs #11, #178).
- Recovery now scans each segment with a streaming reader that reads one record at a time, instead of buffering the whole record region and materializing every record's payload (#156). On a full 64 MiB segment the old path allocated the entire region plus an owned copy of every record (~2x the segment); recovery only needs each record's sequence, the valid record count, and the torn-tail boundary, so the new `SegmentReader::scan_recovery` validates each frame (header and body CRC, sequence continuity) and drops the bytes, bounding peak memory to the largest single record. The buffered `SegmentReader::scan` is retained for the delivery read path. Behavior is unchanged: a new `codec::decoded_len` reads a frame's length from its header, and a test pins that `scan_recovery` agrees with `scan` on count, last sequence, `valid_end`, clean, and footer across clean, sealed, empty, torn, and corrupt segments; the crash-recovery and determinism sweeps pass at 20000 cases (refs #115, #21).

### Fixed
- `ironbus_quarantine_bytes` now reflects the PERSISTED on-disk quarantine footprint, surviving restart, instead of only this-recovery's captured bytes (#315). `Log::open` seeds the gauge from a one-time read-only scan of the durable `quarantine/` blobs even when there is no new corruption skip, so a clean reopen surfaces the real disk pressure rather than reading 0. The scan is best-effort and never blocks recovery: it probes `subdir_exists` first (a clean log never materializes the subdir), and a missing or unreadable dir degrades to 0 without failing `Log::open`, preserving the #134 copy-not-move and never-blocks-recovery properties. Quarantine eviction is now true-FIFO: it orders blobs by the parsed numeric `(segment_id, start, end)` tuple instead of the lexical file name, so two blobs in one segment whose unpadded-decimal offsets sort differently lexically (`-100-` before `-9-`) are evicted in true offset order; an old-format or foreign blob name that does not parse is handled best-effort (evicted last, never a crash). The gauge stays a GAUGE (no `_total`), so the frozen resilience-counter taxonomy is unaffected. `docs/METRICS.md` updated (Closes #315).
- Closed the residual default-group broadcast bypass (#288): `set_broadcast_in(group, true)` now rejects the DEFAULT/empty group with the typed `EngineError::BroadcastGroupNotNamed`, so `serve --broadcast-group ""` is a clean startup usage error. The group-of-one subscriber cap binds only a named group; the default group's consumers never SUB a name, so an uncapped broadcast default group could still let two pollers hold competing in-flight leases that a cumulative ack commits past. `--broadcast-group` now marks a NAMED group only. Added an over-the-wire liveness test that a disconnect frees a broadcast group's group-of-one slot (a later SUB succeeds), plus the default-group reject tests at the engine and CLI layers (refs #288, #63).
- Enforced the broadcast group-of-one invariant in code, closing two reachable silent-drop paths in the broadcast cumulative ack (#288, #63). The `broadcast` flag only gated the verb; it did not restrict membership, so two connections could SUB one broadcast group and hold competing in-flight leases, and a cumulative ack would then commit past (silently drop) a peer's unacked message. A broadcast group now accepts AT MOST ONE active subscriber: a second concurrent SUB is rejected with the typed `EngineError::BroadcastGroupBusy` (over the wire, a typed `Err`), and `set_broadcast_in(group, true)` refuses to flip a group that already carries competing in-flight state (live in-flight leases, an out-of-order acked-ahead set, or more than one subscriber). The slot frees on UNSUB, a subscription switch, or disconnect. The legitimate single broadcast consumer cumulative-acking past its OWN in-flight leases is unchanged, as is the work-group HARD-REJECT. Regression tests reproduce both exploits and the valid case (refs #288, #63).
- Made the `installer_verify` tests deterministic on the parallel macOS CI runner. The test-only `tempdir` module named directories from `pid` + `SystemTime::now()`, but all six tests share one process (one `pid`) and the macOS clock is coarse enough that two fixtures in the same tick collided on one path; the first `TempDir` to drop then deleted the sibling's dir mid-run, surfacing as a spurious `verify_checksum` exit 2 (it flaked #323). Added a process-wide atomic counter to the name and switched `create_dir_all` to `create_dir` so any future collision fails loudly. Test-only fix; no shipped code or installer behavior changed.
- Build fix: the non-unix `cmd_serve` stub now consumes `config.enable_admin`, so `ironbus-cli` compiles warning-clean on Windows under `-D warnings` (the `/admin` field from #99 was only read on the Unix serve path). No behavior change (`serve` is Unix-only) (refs #99).
- Refreshed `docs/USAGE.md` to match the shipped CLI. Added the seven `serve` flags its table omitted (`--allow-unlimited-deliver`, `--backoff-ms`, `--consumer-credit`, `--consumer-credit-bytes`, `--max-groups`, `--disk-full-policy`, `--key-shared-group`), each default verified against the `main.rs` constants and `docs/CLI.md`, and corrected the stale "no graceful-shutdown drain" claim to describe the current SIGINT/SIGTERM/SIGHUP handler that flushes every work-group's cursor and exits 0 (no acked-message redelivery; the optional in-flight drain is still not implemented, so un-acked in-flight messages still redeliver, correct at-least-once). Docs only (refs #15, #136, #287).
- The `ironbus_recovery_loss_bytes` metric's `# TYPE` line no longer carries leading whitespace (a source-indentation artifact), so a strict Prometheus parser recognizes the type declaration; a test now pins the clean `# TYPE` lines (#16).
- `InMemoryFile` modeled `fdatasync` (`sync_data`) and `fsync` (`sync_all`) identically, treating a `set_len` truncation as durable after either (#158). A real `fdatasync` flushes data but need not persist a length-shrink (metadata), so the simulation now reverts a truncation that was only `sync_data`'d on a power loss and persists it only after `sync_all`, while in-place edits and data growth stay durable under `fdatasync`. This pins the conservative real-disk contract that `Log::recover` already follows (truncate a torn tail, then `sync_all`); a regression that truncated with only `sync_data` would now fail the crash-recovery sweep. Includes two model tests and updates the recovery-idempotence gate's torn-tail setup to make the truncation durable via `sync_all` (refs #6, #21).
- The `dead_letter_iff_a_finite_cap_is_exceeded` delivery proptest no longer relies on a `prop_assume!` that rejected ~2.5% of inputs: under a deep (nightly) sweep that exhausted proptest's global-reject budget and aborted the test. The strategy now generates only valid configs (max == 0 forces the unlimited opt-in), so it rejects nothing and is robust at any case count (refs #21).

### Added
- `docs/COMPACTION.md`: the DESIGN spec (specified, not yet implemented) for optional, opt-in, Kafka-style key-based log compaction (#83), reconciled with IronBus's no-manifest directory-of-self-describing-files model. A compacted segment self-describes its covered offset/sequence range in a CRC-protected v2 compaction-metadata footer block (leaving the header reserved bytes `[44, 60)` to at-rest encryption #108) plus a `COMPACTED` header flag, forcing a v2 format bump so a v1 reader fail-closes. The single atomic commit point is the durable appearance of the new segment (directory fsync); recovery resolves any compacted-vs-original overlap from the files alone via longest-valid-prefix with no compaction-specific repair. Covers the full acceptance design (last-value-per-key, tombstone TTL, never reorder/rewrite offsets, sparse-offset reader tolerance with a non-loss `Compacted` gap reason, cleaner OFF by default and append-priority, `compact_and_delete`). Docs only (Closes #83).
- `docs/BACKPRESSURE.md`: the DESIGN spec (mostly specified, not yet implemented) for two overload controls under the backpressure parent (#10), covering both #68 and #69. CoDel (RFC 8289) time-in-queue shedding (#68): shed on sojourn not depth so the control is rate-independent and needs no per-device tuning; TARGET 5 ms / INTERVAL 100 ms defaults exposed per topic via #14 but clamped (TARGET [1 ms, 1 s], INTERVAL [20 ms, 10 s]); the `INTERVAL/sqrt(count)` drop-spacing law; sojourn measured on the monotonic clock seam (`Clock::now_monotonic_nanos`), clamped `>= 0`, with the interval window reset across a detected suspend/resume gap so a sleeping edge device cannot misfire; a sojourn-independent depth-and-byte backstop that fires the overflow policy when a fully stalled drain produces no sojourn samples, proven to bound memory under a total stall. Retry budget, shedding, and do-not-retry signaling (#69): a per-client retry budget of 10% of the client's request rate over a sliding 60 s window (SRE adaptive throttling, accept-based, K~2) enforced client-side AND re-checked broker-side; the structured `retry_after_ms` (0 = retry-now, 0xFFFFFFFF = do-not-retry/shed) and `shed` wire fields specified for #11; a separate per-connection fire-and-forget token bucket (5000 msg/s, 5 MiB/s, 100 ms refill) that caps the uncontrolled tier and cannot evict credited traffic; a static-floor-16 egress AIMD concurrency limiter bounded [4, 128] (+1 clean window, x0.5 on timeout/429/503) with Vegas/Gradient2 deferred behind the interface; proven not to amplify into a retry storm. New #14 config keys and #16 metrics tabled (CoDel shed and backstop shed split; retry/fire-and-forget/egress shed counters; sojourn-estimate, retry-ratio, and egress-limit gauges), each following the frozen-taxonomy rule. Defines a four-primitive portability shim (preallocate, file-datasync, directory-sync, sealed-read-map) over the existing `RandomAccessFile`/`Filesystem` IO seams: the three durability primitives are already implemented, preallocate is the one specified, mapped to its per-OS syscall with a per-OS durability note (Linux `fallocate`/`posix_fallocate`, macOS `fcntl(F_PREALLOCATE)`+`ftruncate`, Windows `SetEndOfFile` plus the privileged `SetFileValidData` caveat) and a fallback ladder down to today's grow-on-append. - Broadcast-consumer cumulative ack (ack-all-up-to-offset), the safe broadcast half of the `JetStream` `AckAll` verb. A group marked BROADCAST (a group-of-one that sees every record in order) accepts `Engine::cumulative_ack_in`, which commits its single cursor up to an exclusive `up_to` via the new `AckCursor::commit_up_to` (idempotent, monotonic, never regresses). `up_to` is validated against the durable head and the earliest-retained offset (out-of-range is the typed `EngineError::CumulativeAckOutOfRange`, never a panic). - `docs/AUTHENTICATION.md`: the normative (specified, not yet implemented) connection-scoped authentication and three-scope authorization contract. Specifies the three v1 mechanisms (bearer token stored as SHA-256 with a constant-time compare, username/password hashed with Argon2id at m=19 MiB / t=2 / p=1, mTLS whose identity is the first URI-then-DNS SAN with CN excluded and a verifying-but-unmatched cert rejected), the three explicit scopes (publish, subscribe, admin, where admin does not imply the others) with the admin-gated verb and #15 diagnostic list, additive credential-set rotation with no expiry timer, and a single uniform Authorization Violation error with no bad-credential-vs-insufficient-scope oracle, binding identity to the connection in the #11 CONNECT handshake. - Bounded, allocation-free metric registry: two fixed-bucket-set histograms (`ironbus_fsync_duration_seconds`, `ironbus_append_duration_seconds`, the compile-time seconds set `{0.0005..5}`), incremental per-consumer lag (`ironbus_consumer_lag_records{consumer}`, O(1) on append/commit and never scanned on scrape) with a hard 1024-series cap that folds overflow into `{consumer="__overflow__"}` and increments the new `ironbus_consumer_labels_dropped_total`, and self-monitoring series (`ironbus_build_info`, `ironbus_start_time_seconds`, `ironbus_uptime_seconds`, clock-seam-derived). The overflow fold is IDEMPOTENT: each distinct over-cap consumer's floor is tracked in a bounded fold-ledger (a second capped array, part of the fixed ceiling, not an unbounded map), so an over-cap consumer re-committing on every ack does not double-count: `ironbus_consumer_labels_dropped_total` counts distinct labels once each and the `__overflow__` lag stays exact (it does not rise as a folded consumer makes progress); past the ledger capacity the overflow lag degrades to a documented monotonic lower bound. The registry has a fixed ~161 KiB memory ceiling (the two capped arrays) independent of record count or disk size, asserted by a test and signed off against the 64 MiB edge RAM budget. An allocation-counting test proves the per-message append/commit path and the registry read walk a scrape performs never heap-allocate; the Prometheus text body itself is serialized into a `String`, so it allocates (the alloc-free guarantee is the append path and the registry read side that feed it, not the text serialization). The dropped counter joins the frozen resilience-counter taxonomy (refs #97, #16).
- Forensic QUARANTINE store on the recovery corruption-skip path (#134). When recovery skips a CORRUPT region (a failed record header or body checksum, distinct from a clean torn tail) it now COPIES the corrupt bytes into a `quarantine/` subdirectory before truncating them away, for offline analysis, while recovery is UNCHANGED (truncate, bounded loss). Copy-not-move: the live segment is read read-only and the truncation is what trims it, so a crash mid-copy can never lose the evidence. Blobs are named `q-<segment-id>-<reason>-<start>-<end>.bin` for off-device pull. Capped by a new `LogConfig::max_quarantine_bytes` (default 256 MiB, `0` = unlimited, the issue's `min(256 MiB, 5% of FS)` ceiling deferred to the server config layer); on reaching the cap it evicts OLDEST blobs first (FIFO), and a single span larger than the whole cap is skipped (metadata-only fallback deferred). Best-effort and never blocks recovery: a quarantine IO failure is swallowed and never fails `Log::open` or touches the live log, exactly like the counters snapshot. The store lives in a subdirectory recovery never scans as live data. Exposed on `/metrics` as the `ironbus_quarantine_bytes` GAUGE (not a `_total`, so the frozen resilience-counter taxonomy is untouched). - The broker now persists the durable consumer cursor on the online path (#182). The engine checkpoints the committed offset once it advances at least `checkpoint_interval` offsets (`EngineConfig.checkpoint_interval`, default 1024 in `ironbus serve`), and the server also flushes it on a clean disconnect, so a restart resumes past acked messages instead of redelivering the whole log. This bounds crash redelivery to roughly `checkpoint_interval` while keeping the checkpoint write rate far below one per ack (edge flash endurance). - `ironbus-cli`: the `ironbus` command-line binary, the first three verbs of the frozen command map (#136). `serve` runs an on-disk broker (creates the data dir, opens the durable engine on `StdFs`, binds loopback by default, serves until the process is signalled; Unix only in v1 with a clear error elsewhere, since on-disk storage is Unix-only). `pub` connects, appends one message (payload from an argument or stdin), and prints the durable offset. `sub` fetches up to a credit, prints one line per message, and with `--ack` acknowledges each (committed or fenced). - `ironbus-client`: a synchronous client library. `Client::connect` handshakes with a broker over TCP, then `produce` (returns the assigned offset), `fetch` (returns the delivered messages, each with the offset and fencing generation), `ack` (returns whether it committed or was fenced), and `ping`. It frames the byte stream with a persistent buffer (so a read delivering several frames is never lost) and maps a server `Err` frame to a typed `ClientError`. Connect, read, and write timeouts (`ClientConfig`, finite defaults) bound every blocking call, so a silent or slow broker fails the call instead of wedging the caller forever. The client distrusts the peer's framing: it rejects an unknown frame tag (`ClientError::UnknownFrameType`), a wrong-shape `Ok` (a non-one-byte ack status or non-eight-byte produce offset, `ClientError::BadResponse`), and more deliveries than the requested credit. Tested with a real produce/fetch/ack round-trip and multi-message fetch against an in-process server, plus hostile-server cases (server `Err`, fenced ack, eight-byte-`Ok` ack confusion, over-credit fetch, unknown tag) against a scripted raw socket.
- Consumer fetch path: a client can now receive and acknowledge messages, completing the produce/consume loop over TCP. `ironbus-proto` adds a `Deliver` frame type and a `DeliverBody` codec (offset + lease generation + the message); `ironbus-server`'s session handles a `Flow` (fetch) request by polling up to the requested credit and streaming each message as a `Deliver` frame, terminated by an `Ok` carrying the delivered count, then the client acks each by its fencing token. `Engine::poll_now` polls using the engine's own clock. Tested end to end, including a full produce -> fetch -> ack round-trip over a real TCP socket.
- `ironbus-server::clock::SystemClock`: the production `Clock` over the OS clock (wall from `SystemTime`, monotonic from `Instant`), the real implementation of the seam `ironbus-core` cannot provide while staying IO-free.
- `ironbus-server::server`: a blocking, thread-per-connection TCP server. `serve` accepts connections until a shutdown flag is set, bounded by a connection cap (so a flood cannot spawn unbounded threads), and drives a `Session` per connection against the engine shared behind a `Mutex` (the single logical writer the storage layer requires; group-commit behind an append actor is a throughput follow-up). Integration-tested over real localhost sockets: a CONNECT+PUB round-trip appends to the engine and returns the assigned offset, and a malformed frame closes the connection.
- `ironbus-server::session`: the connection session that frames the wire protocol onto the engine. `Session::process` consumes the complete frames at the front of an input buffer (leaving a partial trailing frame for the next read) and writes response frames, dispatching the request/response verbs: Connect -> Info, Ping -> Pong, Pub -> Ok (with the assigned offset) into the engine, and Ack -> Ok (committing a delivered message via its fencing token). Pub/Ack before Connect, malformed bodies, and unsupported verbs reply Err without closing; a malformed frame envelope ends the session (a length-prefixed stream cannot resync). Synchronous and buffer-driven, so the async TCP server can drive it without owning IO.
- `ironbus-server::engine`: a durable consumer cursor. The engine now keeps the committed offset in a crash-safe `Checkpoint` (`cursor.ckpt` in the data directory); `checkpoint_cursor` records it, and `Engine::open` recovers it and resumes, so a restart redelivers only the uncommitted tail instead of from zero. The checkpoint is an optimization that may lag (a stale checkpoint redelivers a few already-processed messages, never loses one) and the recovered offset is clamped to the durable log head. Tested across reopen for resume-from-committed, idle-after-full-consume, stale-checkpoint redelivers-the-tail, and a StdFs-backed real-directory run.
- `ironbus-storage::checkpoint`: a crash-safe `Checkpoint` for small durable state (the committed consumer cursor, later the resilience counters). Two CRC32C-protected slots are written alternately by sequence and fsynced; on recovery the higher-sequence slot whose CRC validates wins, so a slot torn by a crash mid-write is ignored and the prior value survives. The checkpoint can regress to an earlier durable value after a crash (safe at-least-once: some processed messages redeliver) but never advances to a torn or invented one. Tests cover round-trip, latest-wins, a torn newest slot falling back, both slots torn recovering nothing, and power loss before the sync keeping the prior value.
- `ironbus-server::engine`: the single-topic queue engine, the synchronous heart that wires the durable log to the consumer primitives. `Engine::produce` appends a message and fsyncs before returning; `poll` hands out the next deliverable message (within a `max_in_flight` sliding window above the committed cursor) under a fencing token; `ack` commits it and advances the cursor over the contiguous prefix. An unacked message past its visibility timeout is redelivered on a later poll (fencing the stale token), and a message over max-deliver is parked rather than looping. Synchronous and deterministic (the caller supplies monotonic time), so the whole produce/consume/recover loop is testable without a runtime; the durable consumer cursor is follow-up, so a restart currently redelivers from zero (safe at-least-once).
- `ironbus-proto::message`: codecs for the PUB and ACK frame bodies (the produce and acknowledge wire messages). PUB carries flags, a producer timestamp, a u16-length key and headers, then the payload as the remainder; ACK carries the op (ack/nack/term/progress), the offset, the lease generation (fencing token), and a nack delay. Decoding is bounds-checked and never panics on a malformed body (typed `BodyError`), little-endian and portable; proptest round-trips and a never-panics-on-arbitrary-bytes property.
- `ironbus-proto::frame`: the wire frame envelope. A frame is a little-endian `u32` length prefix over a one-byte type tag (the verb: Connect, Info, Ping/Pong, Pub, Sub/Unsub, Ack/Nack, Flow, Ok/Err) plus a type-specific body. `encode_frame` and the streaming `decode_frame` validate the length against a 16-MiB-plus cap BEFORE allocating (so a hostile prefix cannot force a large read), report how many bytes a frame consumed or still needs, and let an unknown type tag decode at the envelope level for forward compatibility. Proptest round-trips, truncation-is-incomplete, and unknown-tag framing.
- `ironbus-core::delivery`: the delivery policy (`DeliveryConfig`) and the ack vocabulary (`AckVerb`: ack, nack with an optional delay, progress, term). `disposition` dead-letters a message once it exceeds `max_deliver` (default 5) and otherwise delivers; an unlimited cap (0) is rejected without an explicit opt-in and never dead-letters. `nack_backoff` returns the escalating per-attempt retry delay, clamped to the schedule's last entry. Pure and IO-free; the durable DLQ move (append plus tombstone under one fsync, idempotent on recovery) is the server's job.
- `ironbus-core::lease`: the SQS-style lease lifecycle (`LeaseTable`). A claimed message is in-flight for a visibility timeout; only an ack carrying the matching generation token removes it, an expired lease is redelivered under a bumped generation (fencing the previous holder, so a late ack after redelivery is rejected: no double ack), and `progress` extends the deadline by one window but never past a hard cap from the attempt start. The delivery count rides each grant for the max-deliver / DLQ decision. Pure and IO-free (the caller supplies monotonic time from the clock seam); a restart empties the table so every in-flight message redelivers.
- `ironbus-core::cursor`: `AckCursor`, the work-group commit cursor that advances one shared committed offset correctly under out-of-order acks. It keeps the watermark below which everything is acked plus a compact run-length-encoded set of offsets acked ahead of it, advancing the watermark over the contiguous prefix as gaps fill, so parallel draining never skips an unacked message (at-least-once) nor serializes the group. Duplicate acks are ignored; `resume` rebuilds it from a recovered committed offset. Pure and IO-free, proptest-verified (any ack permutation fully commits; ranges stay sorted, disjoint, non-adjacent; committed is monotonic).
- Crash-injection gates for the storage log (issues #21, #55): a per-PR integration harness that power-cuts the log at every durability boundary and corrupts segments, then asserts recovery yields a consistent, monotonic prefix with no acknowledged record lost and bounded, valid loss. Covers power loss before fsync (at every op boundary, with and without rolling, plus a randomized proptest), a torn (truncated) tail, last-record and mid-log corruption, and arbitrary single-byte corruption (never panics; a valid prefix or a clean error).
- `ironbus-storage::log`: the read path. `Log::read_from(start, max)` reads records from a log offset forward, crossing sealed and active segments, and is bounded by a new durable flushed offset (`Log::flushed_offset`) so a reader never observes a record that is not yet on stable storage. `sync` (and a roll, which fsyncs the sealed segment) advances the flushed mark. An in-memory segment directory maps an offset to its segment by binary search; reading below the oldest retained offset returns `StorageError::OffsetOutOfRange`.
- `ironbus-storage::log`: segment rolling and multi-segment recovery. `LogConfig` sets a soft per-segment size cap (default 64 MiB); `append` seals the active segment and starts the next one, continuing the offset and sequence space, once it reaches the cap (an empty segment is never rolled, so an oversized record still gets written). The old segment is sealed before the new one is discoverable, so a crash mid-roll is recovered by rolling forward: `Log::open` now treats a sealed highest segment as create-the-next-segment rather than an error. A fatal mid-roll error freezes the writer (`StorageError::WriterFrozen`) instead of risking a corrupt resume.
- `ironbus-storage::log`: the single durable, ordered `Log` (write path over one active segment). `Log::open` recovers the active segment, truncating any torn or unsynced tail to the last intact record, or creates a fresh segment 0 stamped from the clock seam and dir-synced; `append` assigns each record its monotonic offset and sequence and writes it; `sync` makes records durable. Reopening after a simulated power loss recovers exactly the synced prefix and reuses (never skips) the dropped record's offset and sequence. Segment rolling and the read path are follow-ups.
- `ironbus-storage::segment::SegmentWriter::resume`: reopen an already-validated segment at its recovered write head without rewriting the header (the recovery primitive `Log::open` uses).
- `ironbus-storage::naming`: segment file naming (`seg-<16-hex-digit-id>.log`, fixed width so lexicographic order equals segment-id order), a strict canonical parser that is the exact inverse of the name function (proptest round-trip both ways), and `segment_ids`, which enumerates a data directory in ascending segment-id order while skipping foreign files. The directory of self-describing files is the discovery authority, no manifest required.
- `ironbus-storage::fs`: a `Filesystem` seam (open, create-new, list, remove, exists, sync-dir) over one flat data directory of segment files, with an `InMemoryFs` that models directory-entry durability (a created-but-not-dir-synced file vanishes on power loss; a removal that was not dir-synced is undone) and a Unix `StdFs` that rejects names escaping the data directory. This is the substrate for the multi-segment log and recovery.
- `ironbus-storage::segment`: `SegmentWriter` (append records, sync, seal with footer) and `SegmentReader` (validate header, scan records, recover the valid prefix on a torn or corrupt tail), wiring the record and segment codecs to the `RandomAccessFile` seam. Tests cover round-trip, seal/scan, empty sealed segments, torn-tail recovery, power-loss (only synced records survive), and rejection of a footer bound to a different segment.

### Documentation
- Documented the cross-platform durability barrier and resolved #153: an acknowledged produce always clears a true device write-barrier. On Linux (the production musl target) that is `fdatasync`/`fsync`; on Apple targets `std` maps both `sync_data` and `sync_all` to `fcntl(fd, F_FULLFSYNC)` (a real drive-cache flush, not a plain `fsync`), which is exactly what `StdFile` relies on, so no redundant `fcntl` wrapper is added. Verified against the `std::sys::fs::unix` source. IronBus deliberately keeps `std`'s no-`ENOTSUP`-fallback behaviour: a filesystem that cannot honour the barrier freezes the writer and stops acking rather than silently downgrading durability. Added a platform durability table to the usage guide, a load-bearing comment on the sync path, and an Apple-gated test that exercises the `F_FULLFSYNC` path.
